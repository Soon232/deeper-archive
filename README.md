# 곰곰 — 디퍼 언브랜딩 살롱 아카이브

디퍼 언브랜딩 살롱에서 쌓은 인사이트(주간 성찰)와 과제 결과물을 모아 두는 공개 웹 아카이브.
정적 HTML만 쓰고(빌드 도구·프레임워크 없음), GitHub Pages로 배포한다.

- 주소: https://soon232.github.io/deeper-archive/
- 검색엔진 비노출: 모든 페이지 `<head>`에 `<meta name="robots" content="noindex, nofollow">`. **새 페이지에도 빠짐없이 넣는다.**
- 배포: main에 푸시하면 `.github/workflows/deploy.yml`이 자동 배포 (Settings → Pages → Source = GitHub Actions)

## 콘텐츠를 쌓는 규칙

나중에 나(또는 다른 클로드 세션)가 페이지를 더할 때 지키는 약속.

**파일명은 `YYMMDD.html`로 통일한다.** 날짜순으로 자연히 정렬되고,
새 글은 같은 규칙으로 떨어뜨리면 목록에 한 줄씩 쌓인다. 같은 날 여러 개면 `YYMMDD-키워드.html`.

**인사이트 리포트는 "결과물 먼저, 성찰 나중"으로 쓴다.**
- 먼저: 그 주에 실제로 만든 것을 눌러볼 수 있게 보여준다. 링크·이미지·카드,
  그리고 **어떻게 만들었는지(쓴 프롬프트·방법)를 같이 공유**한다. 이게 리포트의 중심이다.
- 나중에: 성찰은 하단에 **짧은 항목(제목 + 한두 줄)** 요약으로. 긴 문단으로 풀지 않는다.

**성찰은 내 것만 쓴다.**
- 내가 실제로 겪고 느낀 것만 성찰에 넣는다. AI가 조사·판단한 내용은 성찰이 아니다.
- 내가 쓰지 않는 단어를 얹지 않는다. 그럴듯한 요약보다 실제로 한 일을 그대로.
- AI(에이전트)가 어떻게 판단하고 일했는지는 **별도 섹션에 그 목소리로** 싣는다.
  살롱에서 이 꼭지가 특히 도움이 된다는 반응이 있었다.
- 비유보다 직접적인 표현을 쓴다.

**공개 저장소라는 걸 잊지 않는다.**
- 병력·가족·실명·사연 같은 사적인 내용은 공개본에 싣지 않는다.
  과제가 개인의 몸이나 건강을 다룰 땐 **내 응답·증상은 빼고 일반 자료로만** 정리한다.
- 원본(사적인 대목이 든 정본)은 로컬이나 비공개 저장소에만 둔다.
  공개본은 그 **사본**이고, 고칠 일이 생기면 **정본을 먼저 고치고 다시 옮긴다.**
- 공개본에 다른 사람과의 관계나 거리를 적지 않는다 — 당사자가 읽는다.

**팔레트 예외는 문서로 남긴다.**
어떤 결과물 페이지는 자기 고유의 색을 갖는 게 맞다(상품 상세·발표 슬라이드 등).
그럴 땐 아카이브 팔레트를 벗기고 그 색을 쓰되, **왜 예외인지 아래 표에 한 줄 적는다.**

| 페이지 | 예외 이유 |
|---|---|
| `insight/260828-밤하늘.html` | 디퍼 OS 밤하늘 고유의 초록·금빛 판을 그대로 살림 |

**새 페이지를 더한 뒤엔 세 곳을 같이 고친다**
① 목록 index.html에 카드/항목 한 줄 ② 이 README의 구조 트리와 표 ③ 커밋.

## 새 인사이트 한 편 추가하는 법

1. `insight/YYMMDD.html`을 만든다 (기존 목록 페이지의 `<head>`와 팔레트를 그대로 복사).
2. 위쪽에 그 주에 만든 것(링크·이미지·프롬프트), 아래쪽에 짧은 성찰 항목을 쓴다.
3. `insight/index.html`의 주석 표시 자리에 새 항목 한 줄을 얹는다 (최신이 위).
4. 이 README의 구조 트리를 갱신한다.
5. 커밋하고 push하면 자동 배포된다.
